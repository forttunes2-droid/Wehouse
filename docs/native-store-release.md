# WeHouse native purchases: release controls

The iOS and Android projects are in `ios/` and `android/`. The web checkout remains on Paystack. Native Worker Pro subscriptions and native Sponsored placements use StoreKit or Play Billing with server verification. Native purchase UI is compiled closed unless `VITE_NATIVE_BILLING_ENABLED=true`; the Edge handlers also require `NATIVE_STORE_PURCHASES_ENABLED=true`. Keep both off while configuring and testing stores.

## Store and backend setup

1. Create the app identifiers and signing accounts in App Store Connect and Google Play Console. Register monthly and yearly **auto-renewable subscriptions** for the paid Worker plan. Register **consumable / one-time in-app products** for each Sponsored market and duration you plan to sell. The Creator links each Sponsored SKU to its rule, duration and NGN quote; the user sees the store's actual localized price.
2. Configure the backend secrets, never a `VITE_` client variable: `APPLE_IAP_ISSUER_ID`, `APPLE_IAP_KEY_ID`, `APPLE_IAP_PRIVATE_KEY`, `APPLE_BUNDLE_ID`, `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`, `GOOGLE_PLAY_PACKAGE_NAME`, `NATIVE_STORE_ENVIRONMENT` (`sandbox` on Test and `production` on the production Supabase project), `WEHOUSE_CRON_SECRET` (at least 32 characters), and `NATIVE_STORE_PURCHASES_ENABLED=true` after sandbox verification. Restrict the Google service account to the required Play Developer purchase permissions.
3. Deploy `native-worker-pro`, `native-sponsored` with JWT verification enabled. Deploy `native-store-reconcile` with JWT verification disabled **only** because it checks the private `x-cron-secret` header before querying any data. Schedule a private POST at least every 15 minutes, monitor non-200 responses and throughput, and increase scheduler capacity before increasing paid volume. The handler checks the oldest 50 subscriptions and 50 Sponsored transactions on each call. Configure store refund notifications or a faster reconciliation schedule before broad release.
4. In Creator, publish the Worker Pro terms and store IDs. Record the platform-specific legal launch approvals, then enable App Store and Google Play sales separately. For Sponsored, set market rules and slots, link the matching store products in Creator, and enable each product only after its store metadata and price have been checked. No code edit is needed to change a market price, but the corresponding store product mapping must match the revised quote.
5. Build a Test app with Test Supabase URL and publishable key, `VITE_NATIVE_BILLING_ENABLED=true`, and `npm run prepare:ios:test` or `npm run prepare:android:test`. Exercise a successful purchase, cancellation, interrupted payment restoration, refund, renewal and paused placement using store sandbox accounts. Use `npm run prepare:ios:release` / `npm run prepare:android:release` with production publishable keys after the production migrations, functions, secrets, scheduler and legal approvals are in place. Xcode and the Apple Developer account are required to sign and distribute iOS builds; Android signing and Play Console access are also external.

Store purchase tokens and claim records are service-only in the database. A phone-reported success never activates an entitlement. A charge that misses its reserved Sponsored slot is retained for Finance review and does not get placement. Store cancellations remain active until paid expiry; refunds and revocations remove access or pause placement when reconciled. Monitor charged orders that require review, reconciliation errors, store API quotas and purchases left unfinished.

Apple sign-in uses the linked identity provider. Recovery of a WeHouse password is a separate one-use provider verification flow; Apple does not provide or reset a WeHouse password. Passkeys are not part of this release and need a separate credential enrollment, cross-device, recovery and revocation design. This repository does not include an iOS App Store submission or signed release package.
